# How to update a generated project

Use this guide to apply template improvements to an existing project that was
originally generated by Copier.

1. From the generated-project root, make the working tree clean. Commit all
   work before you start.
2. Run the update:

   ```bash
   uvx copier update --trust
   ```

   Copier uses the project's `.copier-answers.yml` to identify the template
   and reapply its recorded answers. It uses a three-way merge when both the
   project and template changed a file.
3. Resolve every conflict. Then run the generated project's normal checks:

   ```bash
   uv run pytest
   uv run tox
   ```

4. Review files that the template's `_skip_if_exists` configuration preserves.
   These include `README.md`, `.gitlab-ci.yml`, and the package initializer.
   Use the [template reference](../reference/template-contract.md#update-behavior)
   to decide whether to apply a preserved change by hand.
5. Handle any legacy Claude files. If Copier reports
   `.claude/project.md`, move its project-specific details into
   `.agents/project.md`. Remove the old file, then rerun Copier. Copier keeps
   both files during this move. Agents can therefore read both contexts, as
   required by `AGENTS.md`, until the move is complete.

   After the update, confirm that Claude Code uses the canonical workflow
   tree:

   ```bash
   test "$(readlink .claude/skills)" = ../.agents/skills
   ```

   The guarded task keeps a correct link. For an older copied
   `.claude/skills` directory, it replaces only a tree identical to
   `.agents/skills`. A different directory or link remains intact. Preserve or
   reconcile it, then rerun Copier. Do not remove it blindly.

## Migrate a legacy flat Python package.

The current template uses `src/<package>/`. Before accepting this update,
move an older top-level `<package>/` application deliberately. Do not leave
both paths in the working tree. The generated filesystem gate rejects a split
layout.

1. Start with a clean working tree. Create a backup branch or tag before you
   change the package layout.
2. Create `src/`. Move every application file from `<package>/` to
   `src/<package>/`. Include user-created modules. Copier cannot infer or move
   them.
3. Update `pyproject.toml` so Hatch builds `packages = ["src/<package>"]`.
   Keep or add any Python console commands in `[project.scripts]`.
4. Run `uv run pytest` and `uv run tox`. Fix imports, package configuration,
   and tests before continuing.
5. Update `.agents/project.md` if it describes the old layout, then run
   `uvx copier update --trust`. Copier preserves `pyproject.toml` and
   `.agents/project.md`. It does not overwrite this project-specific work.
   Rerun the checks afterward.
